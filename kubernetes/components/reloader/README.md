# Reloader

Restarts a workload when a Secret or ConfigMap it reads only at start changes
(`kubernetes/clusters/prod/reloader.yaml`, the stakater/reloader chart pinned there, values in
this directory, namespace `reloader`). How the cluster's manifests fit together is in
[`kubernetes/README.md`](../../README.md).

## Why

External Secrets updates a Secret **in place**, under the same name, when its value changes in
OpenBao (it checks every hour). Nothing about the workload changes, so Kubernetes restarts
nothing: an app that read the value as an environment variable, or read a mounted file once at
start, keeps the old one until its pod happens to restart. Reloader watches those Secrets and
ConfigMaps and rolls the workloads that ask for it.

What does **not** need it: a ConfigMap generated by Kustomize with a hashed name (pgAdmin's) -
its name changes with its content, so the workload rolls anyway; and apps that re-read a file
themselves (Gatus' config, Alertmanager's ntfy secret, Alloy, Argo CD's webhook secret).

## Design

- **Opt-in, per workload, naming the object**:
  `secret.reloader.stakater.com/reload: <name>[,<name>]` or
  `configmap.reloader.stakater.com/reload: <name>` on the Deployment, StatefulSet or DaemonSet
  (its own metadata, not the pod template's). Never `reloader.stakater.com/auto`: it would also
  react to Secrets that must not cause a restart, like Zitadel's masterkey.
- **Only listed namespaces** (`watchGlobally: false`, `namespaces` in `values.yaml`, user
  decision): the chart creates a Role in each, and no ClusterRole that could read every Secret
  in the cluster (OpenBao's, the databases', kube-system's). Every listed namespace must exist,
  or the sync fails.
- **The annotations strategy** (`reloadStrategy: annotations`): a restart sets
  `reloader.stakater.com/last-reloaded-from` on the pod template. The default strategy adds an
  environment variable instead, which Argo CD's self-heal would revert - restarting the app
  again. Argo CD ignores the annotation for every kind
  (`resource.customizations.ignoreDifferences.all` in
  [`../argocd/patches/argocd-cm.yaml`](../argocd/patches/argocd-cm.yaml)), so a restart is not
  drift.
- **No restart without a real change**: Reloader compares a hash of the data, so External
  Secrets' hourly refresh with unchanged values restarts nothing.
- **Jobs and CronJobs are ignored**: a changed Secret would otherwise start a CronJob's Job at once
  and recreate Jobs; each run reads its Secrets fresh anyway. `reloadOnCreate` and
  `syncAfterRestart` stay off - together they restart every annotated app when Reloader itself
  restarts (stakater/Reloader#1089).
- Chart 2.2.18 (Reloader v1.4.22); 3.x is Reloader v2 with an enterprise subchart and still in
  beta. The chart's empty container securityContext is filled in for the restricted standard;
  the root filesystem is read-only. Metrics through a PodMonitor.

## Which workloads opt in

| Workload | Watches | Read at start because |
|---|---|---|
| `gatus` | Secret `gatus` | environment variables |
| `pgadmin` | Secret `pgadmin` | the entrypoint reads its `*_FILE` secrets |
| `phpmyadmin` | Secret `phpmyadmin` | the entrypoint reads `PMA_CONTROLPASS_FILE` into the environment |
| `api` (wedding-manuele-robine) | Secrets `api`, `jwt` | environment variables; `jwt` too, so a new key pair arrives together with its passphrase |
| `pwa` (wedding-manuele-robine) | Secret `pwa` | envsubst writes the Maps key into the files at start |
| `zitadel` | Secret `zitadel-db` | environment variable |
| `zitadel-groups` | ConfigMap `zitadel-groups` | Python loads the script once |
| `oauth2-proxy` | Secret `oauth2-proxy` | environment variables |
| Grafana | Secret `grafana-admin` | environment variables |
| Loki | Secret `loki-s3` | environment variables |
| `argocd-server` | ConfigMap `argocd-cmd-params-cm` | `server.insecure` |
| `argocd-repo-server`, `argocd-application-controller` | ConfigMap `argocd-cm` | the polling interval |

Deliberately not: OpenBao (its StatefulSet updates `OnDelete`, so a restart annotation would do
nothing, and its seal key must not change), the databases (CloudNativePG and mariadb-operator
manage their pods and restart them in their own order - never annotate them), Zitadel's
masterkey and first-admin password.

## Opting an app in

1. Its namespace in `reloader.namespaces` in `values.yaml`.
2. The annotation on its workload, naming the Secret or ConfigMap it reads at start - in its
   manifest, or through the chart value that annotates the workload (`deploymentAnnotations`,
   `annotations`, ... - check where it lands with `helm template`).

## Checking it

```shell
kubectl --context d3strukt0r-prod-admin -n reloader logs deploy/reloader
kubectl --context d3strukt0r-prod-admin -n <namespace> get deploy <name> -o jsonpath='{.spec.template.metadata.annotations.reloader\.stakater\.com/last-reloaded-from}'
```

The log names every restart and why.
